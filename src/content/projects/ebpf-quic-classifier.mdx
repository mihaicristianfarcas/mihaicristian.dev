Almost all web traffic is encrypted now, and more and more of it is QUIC. Good
for privacy, awkward for anyone who needs to understand their own network: if
you can't read the packets, how do you know what's on the wire?

Traffic has a shape, though. You can't see what a video call is saying, but a
video call *looks* nothing like a file download: different packet sizes,
different rhythm, different bursts. That's enough to tell them apart without
decrypting a single byte.

This captures QUIC packets inside the kernel, records the shape of each flow,
and hands it to a small neural network that sorts it into one of 102
applications. On flows it never saw in training it gets 88% right. I kept the
whole thing small enough to sit on the edge device itself, instead of shipping
everyone's traffic somewhere else first.

## How it works

An eBPF program attached at the XDP hook sees every packet before the kernel's
network stack does. It picks out QUIC on UDP port 443, and for each flow keeps
the size, direction, and gap of the first 30 packets, plus four histograms of
packet sizes and gaps in each direction. That's the same feature layout as the CESNET dataset the
model was trained on, which is what lets a model trained offline work on live
traffic. When a flow has enough packets, the kernel hands it to user space over
a ring buffer.

The user-space side is Rust. It turns each flow into a feature vector and runs
the model through ONNX Runtime. The model learns an embedding for packet sizes
and timings instead of taking raw numbers, looks for patterns across the packet
sequence with convolutions and self-attention, and fuses that with a smaller
network reading the histograms. It has 2.3 million parameters, and its scores
are calibrated afterwards so its confidence means something.

## How well it does

On held-out flows it's right 88% of the time across all 102 applications. The
harder number is the macro F1 of 0.76, which weights every application
equally: the popular ones are easy, and the long tail of rarely seen apps is
where it still gets confused. Classifying a flow takes about 5.5 ms on a desktop
CPU, inside the 10 ms budget set for the Raspberry Pi 5 it's built to run on.
