Search and replace across a whole project has never had tooling I fully trust.
You either read a quickfix list like a compiler dump, or you fire a `sed`
command blind and hope.

So this one shows you the change before you make it. You type a pattern and
results stream in while the search is still running, with a count that ticks
up as they arrive. Every match gets a before and after in the preview pane, you
pick the ones you want or take them all, and the whole thing is undoable
afterwards anyway. It opens with the word under your cursor or your visual
selection already filled in, so the common case is a keystroke away.

## Being careful with your files

A tool that edits forty files at once has to be paranoid, so most of the work
went into what happens at write time. Before it touches a file it checks the
exact text it's about to replace is still there, so a result that went stale
while you were deciding can't quietly corrupt anything. It keeps each file's
line endings and trailing newline as they were, skips any file you have open
with unsaved changes, and asks before replacing everything when the results
were cut off at the limit.

Undo is held to the same standard. The history persists across sessions, and
undoing checks each file against what was written, skipping any that changed
since rather than clobbering your newer edits.

## Staying fast

Search runs through ripgrep and streams its output, so a large tree never
blocks the editor. Replacements are computed in small chunks between editor
events and written to disk off the main thread, which is what lets a big
rename finish without Neovim ever freezing. It has a health check, sensible
limits on result count and file size, and every keymap can be changed.

I built it because I wanted it, and I use it every day. Other people found it
and use it too.
