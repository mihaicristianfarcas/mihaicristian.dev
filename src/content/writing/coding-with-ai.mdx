---
title: 'My experience coding with AI'
description: 'From initial magic to terminal workflows, agentic loops, and owning your code.'
date: 2026-07-27
---

I was in my first year of college when Copilot was introduced in VS Code, my
main IDE back then. All I can say is that it felt like magic.

Some of my first assignments were three Tab presses away, but both sides of
this new power were already clear to me: writing code would become effortless,
but remembering what you wrote, how you wrote it, and (most importantly) *why*
you wrote it that way would become harder and harder.

Nevertheless, I used it. It was great for boilerplate, but whenever I had to
write code requiring specific, non-trivial logic, it got annoying pretty
quickly. It just couldn't predict what I actually needed, so I ditched it.

Around the same time, I bought a Raspberry Pi 5 and ran it headless. Programming
solely inside VS Code or Cursor was no longer that interesting to me; instead,
I got familiar with the terminal, tmux, and Neovim, and I’m still daily-driving
them today.

Then came what we now call coding agent CLIs, and that changed everything.

Before this shift, the most useful AI features were explaining what was going
on in a codebase or suggesting inline changes inside an IDE. Later, the agent
gained the autonomy to write code directly, leaving me to supervise; approving
commands manually or re-prompting whenever clarification was needed.

Fast-forward to the present: I’m sitting in the airport, waiting for my flight,
prompting Claude running on my Pi all the way back home from my phone over
Tailscale, polishing the UI for the very website you’re reading this post on.
Hell, I could even set up those agentic loops everyone is currently obsessing
over: setting a goal for the AI and checking back once an hour to see if my
code is baked and ready.

Of course, there are serious caveats with this approach, and they aren't hard to
spot. Sure, you can apply a quick fix here and there or tweak a bit of UI. I can
see how well that works, as it's a tight feedback loop I use myself.

But in the end, you need to read the code, engage with it, and *own it*, even if
you didn't write every line by hand. It’s the only way to do serious work,
especially in systems programming or core infrastructure and services.

All of my projects are, in the end, *mine*. Not because I typed every single
line of code, but because I was there making every decision along the way,
from architecture down to shipping. This workflow made me more productive, but
it also exposed me to more mistakes *that I own*, accelerating my learning
journey immensely.

When drawing the line, trusting my judgment and working *with* the AI ended up
being remarkably fruitful. It’s an incredible tool, *if* you know how to use it
wisely. Looking forward to learning many more things and building much more
software that matters.
